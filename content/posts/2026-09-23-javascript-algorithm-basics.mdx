알고리즘 문제를 풀 때 자주 사용하는 JavaScript 문법과 수학 기법을 정리한다. 문자열 메서드는 입력과 출력을 다듬거나 조건을 검사하는 데 쓰고, 최대공약수·최소공배수는 수의 관계를 계산하는 데 쓴다. 2차원 배열은 격자나 상태를 저장하는 기본 자료구조다.

## 1. padStart, padEnd: 문자열 길이 맞추기

### 정의와 사용법

`padStart`는 문자열의 앞에, `padEnd`는 뒤에 문자를 채워 목표 길이에 맞춘 **새 문자열**을 반환한다. 원본 문자열은 바뀌지 않는다.

```js
str.padStart(targetLength, padString);
str.padEnd(targetLength, padString);
```

- `targetLength`: 완성할 문자열의 전체 길이. 추가할 문자 수가 아니다.
- `padString`: 채울 문자열. 생략하면 공백을 사용한다.

채울 문자열이 짧으면 반복하고, 필요한 길이보다 길면 필요한 부분만 사용한다. 원본이 이미 목표 길이 이상이면 잘라내지 않고 그대로 반환한다. `padString`이 빈 문자열이어도 원본을 그대로 반환한다.

```js
console.log("7".padStart(3, "0"));    // "007"
console.log("7".padEnd(3, "0"));      // "700"
console.log("A".padStart(6, "xy"));   // "xyxyxA"
console.log("42".padStart(4));        // "  42"
console.log("1234".padStart(2, "0")); // "1234"
```

숫자에는 직접 호출할 수 없으므로 `String(value)`로 변환한다. 음수의 부호를 별도로 처리해 주는 메서드는 아니다. 예를 들어 `String(-7).padStart(3, "0")`은 `"0-7"`이 된다.

### 활용: 자릿수가 정해진 출력

시간이나 번호처럼 출력 자릿수가 정해져 있을 때 조건문으로 0을 붙이는 일을 줄일 수 있다.

```js
function formatTime(hour, minute) {
  return `${String(hour).padStart(2, "0")}:${String(minute).padStart(2, "0")}`;
}

console.log(formatTime(9, 5)); // "09:05"
```

이 함수는 이미 유효한 시와 분을 받는다고 가정한다. `padStart`는 길이를 맞출 뿐, 시간의 유효성을 검사하지 않는다.

### 활용: 이진수의 자릿수 맞추기

정수를 이진 문자열로 바꾸면 맨 앞의 0이 사라진다. 고정된 폭으로 각 비트를 확인하거나 출력하려면 앞을 0으로 채운다.

```js
const value = 5;
const width = 8;
const binary = value.toString(2).padStart(width, "0");

console.log(binary); // "00000101"
```

단, `width`보다 긴 이진수를 잘라주지는 않는다. 비트 계산 자체에는 비트 연산을 사용하고, 이 방식은 문자열로 표현해야 할 때 활용하면 된다.

`padEnd`는 텍스트 표의 열 폭을 맞추는 등 출력 정렬에 쓸 수 있다. 문자열을 채우는 보조 기능이므로 특정 알고리즘과 억지로 연결할 필요는 없다.

```js
console.log("name".padEnd(8, ".")); // "name...."
```

JavaScript 문자열의 길이는 UTF-16 코드 단위 기준이다. 이모지나 한글이 섞인 출력에서는 길이를 같게 맞춰도 화면에서 차지하는 폭이 같지 않을 수 있다.

## 2. startsWith, endsWith: 접두·접미 문자열 확인

### 정의와 사용법

`startsWith`는 특정 문자열로 시작하는지, `endsWith`는 특정 문자열로 끝나는지 검사하고 `true` 또는 `false`를 반환한다. 둘 다 대소문자를 구분한다.

```js
str.startsWith(searchString, position);
str.endsWith(searchString, endPosition);
```

두 번째 인자의 의미가 다르다.

- `startsWith`의 `position`: 검사를 시작할 인덱스. 기본값은 `0`이다.
- `endsWith`의 `endPosition`: 문자열을 어디까지 볼지 정하는 끝 경계. 해당 인덱스의 문자는 제외하며, 기본값은 문자열 전체 길이다.

```js
const text = "hello.js";

console.log(text.startsWith("hello")); // true
console.log(text.startsWith("Hello")); // false
console.log(text.endsWith(".js"));     // true
console.log(text.startsWith("llo", 2)); // true

// 인덱스 5 직전까지의 문자열 "hello"가 "lo"로 끝나는지 확인한다.
console.log(text.endsWith("lo", 5)); // true
```

일반적인 유효 인덱스 범위에서 `text.endsWith(suffix, end)`는 `text.slice(0, end).endsWith(suffix)`처럼 이해할 수 있다. 다만 음수 인자는 `slice`와 처리 방식이 다르므로 같은 규칙으로 생각하면 안 된다.

### 활용: 시작과 끝 조건으로 필터링

문제에서 “특정 접두사로 시작하는 단어”나 “특정 확장자로 끝나는 파일명”을 찾으라고 하면 조건을 그대로 코드로 옮길 수 있다.

```js
const files = ["test-main.js", "main.js", "test-style.css", "test-util.js"];

const result = files.filter(
  (file) => file.startsWith("test-") && file.endsWith(".js")
);

console.log(result); // ["test-main.js", "test-util.js"]
```

가운데 포함되어 있는지를 찾는 `includes`와 구분해야 한다. `"my-test.js"`는 `"test"`를 포함하지만, `"test"`로 시작하지는 않는다.

### 활용: 한 문자열이 다른 문자열의 접두사인지 검사

문자열 목록에서 접두사 관계가 있는지 찾는 문제는 **정렬 후 인접한 문자열 비교**로 풀 수 있다. 같은 접두사로 시작하는 문자열이 정렬 결과에서 연속으로 모이기 때문이다.

```js
function hasPrefixConflict(words) {
  const sorted = [...words].sort();

  for (let i = 0; i < sorted.length - 1; i++) {
    if (sorted[i + 1].startsWith(sorted[i])) {
      return true;
    }
  }

  return false;
}

console.log(hasPrefixConflict(["119", "97674223", "1195524421"])); // true
console.log(hasPrefixConflict(["123", "456", "789"])); // false
```

`"119"`가 `"1195524421"`의 접두사이므로 첫 번째 결과는 `true`다. 여기서는 같은 문자열이 중복된 경우도 충돌로 본다. 자기 자신과 같은 문자열을 제외해야 하는 문제라면 조건을 추가해야 한다.

문자열 개수를 `N`, 최대 길이를 `L`이라 할 때 인접 비교는 최악의 경우 `O(NL)`이다. 정렬을 비교 정렬로 분석하면 전체는 대략 `O(NL log N)`으로 볼 수 있지만, JavaScript `sort`의 구체적인 복잡도는 실행 환경의 구현에 따라 달라진다.

## 3. gcd, lcm: 최대공약수와 최소공배수

### 정의

**최대공약수(GCD)**는 두 정수를 모두 나누어떨어지게 하는 가장 큰 양의 정수다. **최소공배수(LCM)**는 두 양의 정수의 공배수 중 가장 작은 양의 정수다.

예를 들어 12와 18의 최대공약수는 6, 최소공배수는 36이다. JavaScript에는 이를 바로 계산하는 표준 `Math.gcd`, `Math.lcm` 메서드가 없으므로 직접 구현한다.

### 최대공약수: 유클리드 호제법

두 수를 나눌 수 있는 후보를 하나씩 찾는 대신, 나머지를 이용해 수를 줄인다.

```txt
gcd(a, b) = gcd(b, a % b)

gcd(48, 18)
→ gcd(18, 12)
→ gcd(12, 6)
→ gcd(6, 0)
→ 6
```

`a = q × b + r`에서 `a`와 `b`의 공약수는 나머지 `r`도 나눈다. 반대로 `b`와 `r`의 공약수는 `a`도 나눈다. 따라서 두 쌍의 공약수가 같고, 최대공약수도 유지된다. 나머지가 0이 되면 마지막으로 나눈 수가 답이다.

```js
function gcd(a, b) {
  a = Math.abs(a);
  b = Math.abs(b);

  while (b !== 0) {
    [a, b] = [b, a % b];
  }

  return a;
}

console.log(gcd(48, 18)); // 6
console.log(gcd(7, 13));  // 1: 서로소
console.log(gcd(0, 12));  // 12
console.log(gcd(-12, 18)); // 6
```

이 구현은 정수 입력을 전제로 하며, 부호는 제거하고 계산한다. `gcd(0, 0)`은 양의 최대공약수를 정할 수 없는 경우지만, 이 함수에서는 편의상 0을 반환한다. 양의 정수 두 개에 대해 반복 횟수는 `O(log(min(a, b)))`이고 추가 공간은 `O(1)`이다.

### 최소공배수: 최대공약수로 중복된 인수 제거

양의 정수에 대해 다음 관계가 성립한다.

```txt
gcd(a, b) × lcm(a, b) = a × b
lcm(a, b) = (a / gcd(a, b)) × b
```

두 수를 곱한 뒤 공통 인수가 중복된 부분을 최대공약수로 나눠 제거한다.

```js
function lcm(a, b) {
  if (a === 0 || b === 0) return 0;
  return Math.abs((a / gcd(a, b)) * b);
}

console.log(lcm(12, 18)); // 36
console.log(lcm(4, 6));   // 12
console.log(lcm(0, 5));   // 0
```

위 코드는 앞의 `gcd` 함수를 함께 사용한다. 0이 포함되면 최소공배수를 0으로 반환하도록 확장했고, 음수 입력도 결과는 음수가 되지 않게 처리했다.

먼저 나눈 뒤 곱하면 불필요하게 큰 중간값을 줄일 수 있다. 그래도 결과가 `Number.MAX_SAFE_INTEGER`를 넘으면 정확한 정수 계산을 보장할 수 없으므로, 큰 정수를 다루는 문제에서는 `BigInt`로 구현해야 한다.

### 활용: 약분, 같은 크기로 나누기, 주기 계산

분수의 분자와 분모를 최대공약수로 나누면 기약분수가 된다. 다음 예시는 양의 정수인 분자와 분모를 가정한다.

```js
const numerator = 18;
const denominator = 24;
const divisor = gcd(numerator, denominator);

console.log([numerator / divisor, denominator / divisor]); // [3, 4]
```

가로 12, 세로 18인 직사각형을 같은 크기의 정사각형으로 빈틈없이 나누는 문제에서도 최대공약수를 쓴다. 정사각형의 최대 한 변 길이는 `gcd(12, 18)`, 즉 6이다.

최소공배수는 **같은 시점에 출발한 반복 주기가 다시 만나는 시점**을 구할 때 쓴다. 4분마다 울리는 알림과 6분마다 울리는 알림이 지금 함께 울렸다면, 다음에 함께 울리는 때는 `lcm(4, 6)`, 즉 12분 뒤다. 시작 시점이 다르면 주기만으로 답을 정할 수 없다.

여러 수의 최대공약수와 최소공배수도 두 수씩 누적해서 구할 수 있다.

```js
const numbers = [12, 18, 24]; // 비어 있지 않은 양의 정수 배열

console.log(numbers.reduce((acc, value) => gcd(acc, value))); // 6
console.log(numbers.reduce((acc, value) => lcm(acc, value))); // 72
```

## 4. 2차원 배열 생성: 각 행을 독립적으로 만들기

### 정의와 사용법

JavaScript에서는 배열 안에 배열을 넣어 2차원 배열을 표현한다. `arr[row][col]`로 행과 열에 접근하며, 인덱스는 0부터 시작한다.

```js
const n = 3;
const arr = Array.from(Array(n), () => Array(n).fill(0));

arr[0][1] = 7;
console.log(arr);
// [
//   [0, 7, 0],
//   [0, 0, 0],
//   [0, 0, 0]
// ]
```

이 코드는 세 단계로 이해할 수 있다.

1. 바깥의 `Array(n)`으로 길이가 `n`인 배열을 만든다.
2. `Array.from`이 각 위치에서 콜백을 실행한다.
3. 콜백이 매번 `Array(n).fill(0)`을 호출해 새로운 행을 만든다.

행마다 새 배열을 생성하는 것이 핵심이다. 길이만 필요하다는 의도를 드러내려면 `{ length: n }` 형태로도 쓸 수 있다. 행과 열 크기가 다르면 각각 지정한다.

```js
const rows = 2;
const cols = 3;
const matrix = Array.from({ length: rows }, () => Array(cols).fill(0));

console.log(matrix); // [[0, 0, 0], [0, 0, 0]]
```

모든 칸을 초기화하므로 시간과 공간은 모두 `O(rows × cols)`다.

### 주의: fill에 배열을 넣으면 같은 행을 공유한다

다음 코드는 바깥 배열의 모든 칸에 **같은 배열 참조**를 넣는다.

```js
const wrong = Array(3).fill(Array(3).fill(0));
wrong[0][0] = 1;

console.log(wrong);
// [[1, 0, 0], [1, 0, 0], [1, 0, 0]]
console.log(wrong[0] === wrong[1]); // true
```

한 행만 수정해도 모든 행이 바뀐 것처럼 보인다. `Array.from`의 콜백에서 행을 새로 만들면 이 문제가 없다.

```js
const correct = Array.from({ length: 3 }, () => Array(3).fill(0));
correct[0][0] = 1;

console.log(correct); // [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
console.log(correct[0] === correct[1]); // false
```

`Array(n).map(...)`도 주의해야 한다. `Array(n)`은 빈 슬롯으로 이루어져 있어 `map`의 콜백이 실행되지 않는다. 반면 `Array.from`은 각 인덱스에 대해 콜백을 실행한다.

칸마다 객체가 필요하다면 내부 배열도 `Array.from`으로 만들어야 한다. `fill({ visited: false })`는 같은 객체를 공유하기 때문이다.

```js
const cells = Array.from({ length: 2 }, () =>
  Array.from({ length: 3 }, () => ({ visited: false }))
);

cells[0][0].visited = true;
console.log(cells[0][1].visited); // false
```

### 활용: 격자 탐색과 동적 계획법

미로 탐색이나 섬 개수 세기처럼 격자를 BFS·DFS로 탐색할 때는 방문 여부를 저장할 수 있다.

```js
const rows = 3;
const cols = 4;
const visited = Array.from({ length: rows }, () => Array(cols).fill(false));

visited[1][2] = true; // 1행 2열 방문 처리
```

동적 계획법(DP)에서는 각 칸까지의 답을 저장한다. 예를 들어 장애물이 없는 격자에서 오른쪽과 아래로만 이동할 때, 특정 칸으로 오는 경로는 **위에서 오는 경로와 왼쪽에서 오는 경로**로 나눌 수 있다.

```txt
dp[r][c] = dp[r - 1][c] + dp[r][c - 1]
```

첫 행과 첫 열로 가는 방법은 각각 한 가지이므로 1로 초기화한다.

```js
function countPaths(rows, cols) {
  if (rows <= 0 || cols <= 0) return 0;

  const dp = Array.from({ length: rows }, () => Array(cols).fill(0));

  for (let r = 0; r < rows; r++) dp[r][0] = 1;
  for (let c = 0; c < cols; c++) dp[0][c] = 1;

  for (let r = 1; r < rows; r++) {
    for (let c = 1; c < cols; c++) {
      dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
    }
  }

  return dp[rows - 1][cols - 1];
}

console.log(countPaths(3, 3)); // 6
console.log(countPaths(1, 4)); // 1
console.log(countPaths(0, 3)); // 0
```

시간과 공간 복잡도는 모두 `O(rows × cols)`다. 입력 크기는 정수라고 가정하며, 큰 격자에서는 경로 수가 안전한 정수 범위를 넘을 수 있어 문제 조건에 따라 `BigInt`나 나머지 연산이 필요하다.

2차원 배열은 그 자체가 풀이 알고리즘은 아니다. 각 칸에 무엇을 저장할지 정하고, 행과 열의 의미를 일관되게 유지하는 것이 탐색이나 DP 구현의 출발점이다.
